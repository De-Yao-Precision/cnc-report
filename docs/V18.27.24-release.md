## 修改摘要

老闆總覽與主管看板合併為「即時看板」：六個全廠 KPI、依五級順序排列的待處理機台、全部機台。桌面為七欄群組表格，手機為可展開卡片。保留狀態篩選、機台／製令／圖號／圖名／人員搜尋及六種排序。待處理項目可清除篩選、定位並展開該機台。

目前負責人與班別讀取責任資料；個人產量、應達與達成率沿用 currentPersonStats。待接手量沿用 pendingTakeoverStats，不歸給個人；舊責任資料無法確認時顯示「—」。停機累計沿用 liveDown；換刀使用既有停機事件及 groupId/eventId 去重，限定目前製令實例。

### KPI 定義

1. 生產中：原 status 為生產中，包含持續加工但待接手者。
2. 停機：原 status 為停機。
3. 異常：品質異常狀態，或當班異常 PCS > 0。
4. 待接手：有既有 pendingTakeover 紀錄；與生產中可重疊。
5. 今日實際產量：既有 monthRecords 中 productionDate 為今日的已存＋進行中產量，沿用修正後資料。跨日區段仍依原歸屬日，不推算午夜產量。
6. 今日平均達成率：dailyPersonMachinePerformance 中今日「可確認、已封存」人員×機台群組的總產量÷總應達，為應達加權；未封存或待確認不納入，沒有符合資料顯示「—」。

待接手超時沿用原 pendingOverdueDue（超過30分鐘且尚未進入結算選擇）；資料過期為距更新時間超過2小時；低達成率只看可確認的目前個人績效 <80%。同台可列多個問題，排序以最高優先項目為準。無更新時間不捏造已過期分鐘。

## 驗證結果

本機隔離 Edge，固定 Asia/Taipei 時區、相同測試資料與時間比對原版／新版。80 項通過，JavaScript page errors = 0。

- owner（隔離測試帳號）及 supervisor 共用即時看板；舊 supervisor 路由相容。operator 無頁籤／路由／詳細視窗權限，切換角色時舊管理視窗關閉。
- 停機42分、異常8 PCS、待接手36分／25 PCS、過期121分、低達成率54%等情境，含30分鐘、120分鐘、80%、60%及100%界線。
- 已確認績效加權口徑、未確認排除、個人班別跟責任走、製令換刀事件範圍、無製令不出現NaN。
- 看板渲染前後的機台／責任／製令／停機／報表資料與 localStorage 快照相同。
- 435個既有具名函式來源一致。只修改 renderOwner、renderCards、showDetail、authShowView、authApplyAccess 五個呈現／導覽整合函式；新增 rt 前綴呈現輔助函式。
- 操作員、機台製令班報表、月報、製令歷史、異常品、操作歷程、ERP、系統管理與規則頁的原 section 內容一致。
- 相同資料下原新版機台製令報表、月報／Excel資料、個人績效與停機結果一致；Excel 可下載且為有效 ZIP 檔頭。
- 操作員真實登入／選班別、接手；10分鐘後以原結算函式結算10 PCS／應達10；以畫面按鈕選擇繼續生產，再由操作員回報實際停止，停機時間正確。
- 1440px 桌面及390px手機無頁面水平溢出；搜尋、待接手篩選、低達成率排序、待處理定位、手機展開、原詳細資料及歷史入口均驗證。
- 原檔JavaScript與新版均可解析，git diff --check 通過；保留原 CRLF。

這是合成資料的本機瀏覽器回歸，並非工廠實際資料／所有操作排列的完整驗收；未驗證真實 iPhone Safari、桌面 Excel 開啟或 GitHub Pages 部署。截圖均為測試情境，不是現場生產數據。
