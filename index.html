月報結單製令數「本月生產製令」與「本月結單製令」分開。生產製令數依 segments 去重；結單製令數只計真正執行「製令完成」或「例外結單」所建立的獨立結單事件，不再用本月出現過幾個製令號推算。
結單類型分開月報同時顯示「正常完成」與「例外結單」件數。正常完成＋例外結單＝本月結單製令數。
結單事件保存每次結單保存生產歸屬日、班別、機台、製令、實際完成數、製令數量、操作員、結單類型與例外原因。跨月晚班仍依既有生產歸屬日規則歸月。
月結日期月結稽核紀錄使用該月份真正的最後一天，不再固定寫成「月份-31」。系統會自動判斷大小月與閏年：例如 2026-09 → 2026-09-30、2026-02 → 2026-02-28、2028-02 → 2028-02-29。舊測試資料若曾寫成不存在的月底日期，開啟本版時會自動修正月結 audit 日期。
文字輸入安全製令、圖號、程式號碼、刀號等代碼欄位會限制長度並禁止 HTML 尖括號；備註／補充說明限制長度、拒絕控制字元與 HTML 標籤。所有重要歷史、月報、製令履歷與操作紀錄顯示時使用 HTML escaping，避免使用者文字被當成網頁程式碼。
顯示層防護除了欄位驗證，所有 innerHTML 寫入再經過安全清理，會移除 script、iframe、危險事件屬性與 javascript URL。這是測試版的第二層防護；正式多人版仍需在伺服器端再次驗證與轉義。
WorkOrder 製令主檔每次正式換入新製令時，系統背景自動建立一筆獨立 WorkOrder 主檔，永久保存製令號、機台、圖號、程式號碼、加工模式、加工秒數、製令數量、目前／最終加工、異常、開始時間、結單狀態與結單資訊。操作員不需多按任何按鈕。
WorkOrderEvent 製令事件重要生命週期事件自動綁定到該張製令：製令啟動、接手機台、下班結算、異常品登錄、主管異常修正、停機／恢復、換刀、待換線、開始校車、換出製令、製令完成／例外結單。班別產量細節仍由 segments 保存，避免事件表被每次數量更新塞滿。
製令歷史查詢主管可到「製令歷史（主管）」搜尋製令／機台／圖號／程式號碼，查看 WorkOrder 主檔與 WorkOrderEvent 時間軸。舊資料會盡量由既有結單事件與目前機台狀態回補，但 V18.17 以前的早期事件可能不完整。
舊資料相容舊班別紀錄若沒有 segments，月報會暫時以整班資料回退顯示並標示「舊資料：整班回退」；若舊資料的 wo 已是 MO-A → MO-B，系統無法事後猜出兩張製令各做多少，月結檢核會提出警告。
月結月份流程為進行中 → 待確認 → 已月結。月結前需執行資料完整性檢核。
月結後修改已月結月份不可直接覆蓋；主管重新開啟或建立修正紀錄，必須保存修改人、時間、原因、原值與新值。
歷史下鑽月總覽可往下查看機台、班別、製令與操作歷程，保留原始紀錄作為統計來源。
操作員防呆正常操作快速送出；數量下降、異常暴增、換製令、製令完成、例外結單、下班結算與接手機台等高風險動作要求額外確認。
製令狀態流程鎖製令未結單時不能換製令或校車。結單後有兩條合法路徑：①同品續做可直接換製令；②不同品或需要調機則走待換線／待校車 → 校車中 → 校車完成 → 換製令。
同品續做判斷直接換製令只允許圖號、加工模式、加工秒數都與上一製令相同；製令單號與製令數量可以不同。任一加工條件不同時，系統會阻止直接換製令並要求走校車流程。
製令資料切割即使同品續做不需校車，上一製令仍會保持已結單封存，新製令的累積數、異常數與進度從0重新開始，避免兩張製令數量混在一起。
結單後鎖定製令完成或例外結單後，操作員不能再更新數量、登錄異常品或開始停機；如需修正，正式版由主管修正並保留原值、新值、原因、時間與人員。
停機互斥停機只允許從生產中開始；停機中不能直接結單、待換線、校車或換製令。換製令不會清除本班已累積停機；下班結算不會中斷停機，20:30／08:00真正切班時才切停機分段。
校車產量校車中禁止一般「更新數量／異常品」；校車試車品不直接算正式生產量。校車中仍可登錄換刀，並標示為「校車換刀」。
異常數量防呆製令累積異常品不得超過目前製令已加工數；製令結單後操作員不能再補登舊製令異常。
製令完成數量規則製令完成以「機台累積加工數」達到製令數量為準，不以良品數判定。例：製令1000 PCS、異常10 PCS，累積加工達1000 PCS即可正常結單，良品990 PCS不需要補做10 PCS。
更新數量進度操作員更新數量時即時顯示製令數量、目前累積、異常品、尚欠加工與完成率；尚欠 = MAX(製令數量－累積加工數, 0)。達標、接近完成或超量會顯示不同提示。
數量異常硬擋數量格式錯誤、已月結月份、低於下班結算切點、低於已登錄異常品數量等不合理數值，操作員不可送出；系統直接阻止，不允許按確認後硬通過。
巨大數量增加分級數量增加會依「距離上一筆的時間＋加工秒數」估算合理產量。第一級偏大：操作員可二次確認；第二級極端異常：普通操作員不能直接通過，必須由目前登入主管選擇解鎖原因。主管解鎖只授權這一筆，不會永久解除防呆。
主管解鎖稽核成功解鎖會保存目前登入主管帳號、原累積、新累積、增加量、當時推估量、操作員、原因與時間。舊共用 PIN 已停用；目前為單機測試版驗證，不等同正式伺服器身分驗證。
分段起始累積硬鎖同一張製令內，普通操作員不可把累積數修到低於「目前班別／目前製令生產分段起始累積」。系統同時比較「目前生產分段起始累積」與「最新下班結算切點」，以較高者作為最低可修正值。例：晚班20:30起始3210 PCS，21:00即使目前3250 PCS，也不可修到3000 PCS；若起始值本身有誤，須由主管處理。正式換新製令後累積才可重新從0開始。
分段加工／異常一致性任何數量往下修正前，系統重新計算「修正後本分段加工量」。若修正後加工量小於本分段已登異常量，直接阻止送出。例：分段起始1000、目前1050、分段異常30，若欲修正到1020，修正後分段加工只有20 PCS，小於30 PCS異常，因此普通操作員不可通過，須由主管確認異常紀錄或數量修正。
異常品登錄上限操作員新增異常品時，也必須符合「本分段加工量 ≥ 本分段異常量」。異常畫面會顯示本分段加工、已登異常與目前最多可再登數量；若是補登上一分段／舊製令的異常，交由主管修正流程處理。
異常數量主動輸入異常品數量欄位預設一律空白，不自動帶入1 PCS或任何數值。操作員必須主動輸入大於0的整數；空白、0、負數、小數全部阻止送出。若本分段可再登異常已為0，輸入欄位直接停用並提示由主管確認。
主管異常修正已送出的異常品紀錄不可由操作員修改或刪除。主管可在「異常品紀錄（主管）」找到原始紀錄，依登入權限及已結算／月結再次驗證規則修正有效異常數量或原因；系統新增修正事件，不覆蓋原始紀錄。
異常修正稽核每次主管修正保存：原始異常紀錄ID、原有效數量、修正後數量、差異、原原因、新原因、主管、修正原因、補充說明與時間。修正後仍必須符合製令／班別／分段「異常量 ≤ 實際加工量」。
月結後異常修正已月結月份禁止直接修正異常。必須先由主管在月報頁重新開啟該月份，再進行主管異常修正，完成後重新檢核與月結。
PCS數量一律整數所有以PCS為單位的數量都禁止小數：累積加工數、異常品數量、接手機台實體累積、製令數量、例外結單完成數都必須為整數。例：100、101、5000可接受；100.5、1.5一律阻止送出。加工秒數等非PCS欄位不受此規則限制。
程式號碼程式號碼為選填，可填可不填；有填時會正式保存到機台目前製令、製令分段、班別快照、下班結算事件與上一製令摘要。程式號碼不列入同品續做判斷條件。
材質欄位V18.8 起移除材質輸入與保存欄位，操作員換製令時不再需要輸入材質。
數量往下修正新累積低於上一筆時，不再視為一般「本次增加負數」，而是進入「數量修正模式」。必須填寫修正原因並留下原值、新值、原因、操作人與時間的稽核紀錄。
超製規則真實加工累積可以高於製令目標，系統不得為了配合目標而改小真實數量；尚欠固定最低為0，另顯示「超製量 = MAX(累積－製令數量, 0)」，並在操作與稽核紀錄保存超製數量。
製令目標修正目前操作員介面不提供直接修改正在生產中的製令目標數量。正式版若需把製令目標往下修改，應由主管修正並保留原值、新值、原因、修改人、時間與當時累積，不允許靜默覆蓋。
數量輸入唯一入口正常生產累積數仍只透過「更新數量」修改；「下班結算」只保存當下累積與正常區段產量作為切點，不會歸零、不會切換到下一班。
個人達成率下班結算時，個人達成率 = 此人責任區段實際加工數 ÷ 此人責任區段應達數 × 100%。什麼時間結算，個人產量與應達就算到什麼時間；結算後到下一位真正接手前的產量與時間只列為機台待接手區段，不計入任何人的個人產量、個人應達或達成率。下一位從實際接手時間與接手累積開始重新計算。
提前30分鐘分批結算早班正常下班可於16:30–17:00逐台結算；若未結算代表繼續加班，最終可於20:00–20:30結算。晚班對稱為04:30–05:00與07:30–08:00。
待接手產量例：王先生16:35結算620 PCS，李先生17:15才實際接手650 PCS，620→650的30 PCS列為「待接手產量」，只計入機台總產量，不計入王先生或李先生的個人產量與達成率。李先生從17:15、650 PCS才開始個人績效。
真正換班時間班別只在20:30與08:00由系統自動切換。下班結算不會改變班別，負責人切換也不會改變班別。
正常下班與加班不用另外選早班16:30–17:00／晚班04:30–05:00若有做下班結算，代表目前人員正常下班；若沒有結算，系統直接視為目前人員繼續加班，不需要另外按「繼續加班」。加班人員可於20:00–20:30／07:30–08:00做最後結算。
結算防重複同一位負責人在同一責任區段只能結算一次。結算後必須等下一位「接手機台」後，新的負責人才會重新開啟自己的產量區段。
接手機台人員換手時使用「接手機台」。接手人必須確認實體機台累積數；系統保存原負責人、新負責人、接手時間、累積數、製令與當時班別狀態。接手機台不會切換班別。
負責人與班別分離例：A1早班16:35下班結算後，17:00由另一人接手；17:00後數量仍屬「早班加班」，但目前負責人改成17:00接手的人。
負責人操作鎖更新數量、下班結算、異常、停機／恢復、換刀、結單、校車與換製令等操作，只允許目前負責人執行；其他人必須先使用「接手機台」切換責任。
下班結算切點鎖同一製令完成下班結算後，普通操作員不能把累積數修到結算切點以下；「接手機台」也不能繞過。換新製令後累積正常歸零不受此限制。
管理看板負責人老闆總覽與主管機台卡直接顯示目前負責人與接手時間，避免只看到產量卻不知道目前由誰顧機台。
測試資料模式測試工具分成「示意資料模式」與「乾淨測試模式」。示意模式用於展示；乾淨模式只保留機台清單與系統設定，清除所有生產／歷史測試資料。機台在「待建立製令」時不建立班別紀錄；建立第一張製令後才開始該機台的 shiftSession，避免空白機台污染班別紀錄與月結檢核。
手機操作員介面V18.21只移植同事新增的德曜品牌、6S、淺色操作員卡片、大型觸控按鈕與手機RWD；老闆、主管、月報、製令履歷與規則頁仍完整保留。手機寬度下確認送出按鈕會固定在畫面底部附近，方便現場操作。
乾淨模式班別啟動V18.22修正：待建立製令的空白機台不建立 shiftSession；只有建立第一張製令後才開始班別紀錄。這樣未使用的機台不會出現0 PCS空白班別，也不會讓月結誤判大量機台仍在進行中。
結算文字一致性V18.23修正：所有下班結算、待接手與個人達成率說明統一為同一規則。結算後到下一位真正接手前，只累積機台產量，不計入任何人的個人產量、個人應達或個人達成率；下一位從實際接手時間與接手累積開始計算。
JSON備份／還原V18.24新增：可把目前瀏覽器的測試生產資料整包下載為 JSON，並在同一網站選擇該備份還原。還原前會檢查備份格式、機台清單與資料結構，顯示摘要後再要求人工確認；不接受任意 JSON 直接寫入。
ERP匯入畫面預覽V18.25僅新增主管用的ERP匯入UI示意頁；可操作補機台／程式／加工秒數與查看狀態，但「確認匯入」不會寫入製令、機台、WorkOrder或localStorage。是否正式加入，待流程確認後再決定。
ERP產品編號V18.25.2確認：ERP的「產品編號」不匯入CNC網站，也不自動當作圖號使用；ERP預覽頁只保留品名規格供辨識。

「其他」原因必填異常品、停機、例外結單若原因選「其他」，補充說明立即變成必填。不得只輸入空白、標點符號或純數字，至少要有2個有效字元；例如「卡料」「等品管」可接受，「.」「0」不可接受。若已選明確原因，補充說明維持選填。
停機提醒停機中的機台在操作員頁持續顯示紅色提醒與停機分鐘，並提供快速恢復生產入口。
